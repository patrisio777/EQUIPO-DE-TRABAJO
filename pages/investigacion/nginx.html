Nginx

Servidor web de alto rendimiento, proxy inverso y balanceador de carga utilizado en millones de sitios a nivel mundial.

¿Qué es Nginx?

Origen, arquitectura y por qué es tan popular.

Nginx (pronunciado "engine-x") es un servidor web de código abierto creado por Igor Sysoev en 2004. Fue diseñado desde cero para resolver el problema C10K: manejar más de 10.000 conexiones simultáneas de forma eficiente.

A diferencia de servidores tradicionales como Apache que crean un hilo por cada conexión, Nginx utiliza una arquitectura asíncrona basada en eventos, lo que le permite atender miles de peticiones con un consumo mínimo de memoria.

Hoy en día es usado por sitios como Netflix, Dropbox, WordPress.com y representa aproximadamente el 34% de los servidores web activos en internet.

Funciones principales de Nginx
  • Servidor web: Sirve archivos estáticos (HTML, CSS, JS, imágenes) directamente al navegador del usuario.
  • Proxy inverso: Recibe peticiones del cliente y las redirige a servidores backend (como Node.js, Django o FastAPI).
  • Balanceador de carga: Distribuye el tráfico entre múltiples servidores para evitar sobrecargas.
  • Caché: Almacena respuestas frecuentes para entregarlas más rápido sin consultar al backend.

Nginx vs Apache

Comparación entre los dos servidores web más utilizados.

Característica Nginx Apache
Arquitectura Asíncrona, basada en eventos Basada en procesos/hilos
Rendimiento con archivos estáticos Muy alto, consume poca memoria Bueno, pero consume más recursos
Conexiones simultáneas Maneja miles con bajo consumo Limitado por hilos disponibles
Configuración Archivo centralizado (nginx.conf) Archivos distribuidos (.htaccess)
Proxy inverso Nativo y eficiente Requiere módulos adicionales

Arquitectura de Nginx

Cómo funciona internamente el servidor.

Proceso Master

Lee la configuración (nginx.conf), valida la sintaxis, abre los puertos de escucha y crea los procesos worker. No atiende peticiones directamente.

Workers

Procesos hijo que atienden las peticiones de los clientes. Cada worker maneja miles de conexiones simultáneas gracias al modelo de eventos (epoll/kqueue), sin crear un hilo por conexión.

Event Loop

Cada worker ejecuta un bucle de eventos que monitorea conexiones activas. Cuando una conexión tiene datos listos, el worker la procesa sin bloquear a las demás.

Configuración Básica de Nginx

Estructura del archivo nginx.conf y sus bloques principales.

Bloques de configuración
  • events { }: Define el modelo de conexiones y el número máximo de conexiones simultáneas por worker.
  • http { }: Contiene toda la configuración del servidor web: tipos MIME, logs, compresión y los bloques server.
  • server { }: Define un host virtual: en qué puerto escucha, qué dominio atiende y dónde están los archivos.
  • location { }: Dentro de un server, define reglas para rutas específicas (ej: /, /images/, /api/).
Ejemplo: servir archivos estáticos
server {
  listen 80;
  server_name localhost;

  location / {
    root /usr/share/nginx/html;
    index index.html;
  }
}

Esta es la configuración que usamos en nuestro proyecto con Docker: Nginx escucha en el puerto 80 y sirve los archivos HTML desde la carpeta del contenedor.

Nginx con Docker en Nuestro Proyecto

Cómo usamos Nginx dentro de un contenedor para servir nuestro sitio.

Dockerfile del proyecto
FROM nginx:alpine

COPY . /usr/share/nginx/html

EXPOSE 80

FROM usa la imagen oficial de Nginx basada en Alpine Linux (ligera). COPY copia nuestros archivos HTML/CSS al directorio que Nginx sirve. EXPOSE indica que el contenedor usa el puerto 80.

Comandos para ejecutar
  • 1. Construir la imagen docker build -t sitio-gadc .
  • 2. Ejecutar el contenedor docker run -d -p 8080:80 sitio-gadc
  • 3. Ver el sitio Abrir http://localhost:8080 en el navegador

Directivas Importantes de Nginx

Las instrucciones más utilizadas en la configuración.

Directiva Descripción Ejemplo
listen Puerto en el que Nginx escucha las peticiones. listen 80;
server_name Dominio o nombre del host virtual. server_name localhost;
root Directorio raíz donde están los archivos del sitio. root /usr/share/nginx/html;
index Archivo por defecto cuando se accede a una ruta. index index.html;
location Define reglas para rutas específicas del sitio. location /images/ { ... }
proxy_pass Redirige peticiones a otro servidor (proxy inverso). proxy_pass http://backend:3000;
error_page Define páginas personalizadas para errores HTTP. error_page 404 /404.html;
gzip Activa la compresión de respuestas para mayor velocidad. gzip on;

Flujo de una Petición HTTP

Qué sucede cuando un usuario visita nuestro sitio en localhost:8080.

1. Navegador

El usuario escribe localhost:8080 en su navegador y envía una petición HTTP GET.

2. Docker

Docker recibe la petición en el puerto 8080 y la redirige al puerto 80 interno del contenedor.

3. Nginx

Nginx recibe la petición, busca el archivo solicitado en /usr/share/nginx/html y lo prepara para enviar.

4. Respuesta

Nginx envía el archivo HTML/CSS/JS de vuelta al navegador, que lo renderiza como la página web.

Resumen

Conceptos clave de Nginx aplicados en el proyecto GADC.

Concepto Descripción Uso en el Proyecto
Servidor web Sirve archivos estáticos al navegador. Nginx entrega nuestros HTML, CSS e imágenes al usuario.
nginx:alpine Imagen Docker oficial ligera de Nginx. Base de nuestro Dockerfile para el contenedor.
Puerto 80 Puerto estándar HTTP dentro del contenedor. Mapeado a 8080 en el host con -p 8080:80.
root Directorio raíz de los archivos del sitio. /usr/share/nginx/html contiene nuestro proyecto.
index Archivo por defecto al acceder a una ruta. Nginx sirve index.html al visitar la raíz.
Proxy inverso Reenvía peticiones a servidores backend. No usado en este lab, pero es una capacidad clave de Nginx.
